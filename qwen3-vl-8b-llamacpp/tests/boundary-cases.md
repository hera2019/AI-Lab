# 多模态边界测试矩阵

本文记录输入、问题与判定方法。模型已经下载，各阶段的精确结果保存在 `results/`；本文件继续作为固定测试矩阵使用。

## 判定分层

每个测试分开记录三层结果：

1. **传输与解码**：文件能否被 CLI/API 接收；坏文件能否快速、明确地拒绝。
2. **libmtmd 预处理**：尺寸、方向、透明度、图片顺序和 token 数是否合理。
3. **模型答案**：OCR、计数、颜色、关系和不确定性表达是否正确。

只有崩溃、挂死、异常内存、静默忽略图片、CLI/API 行为不一致等实现问题，才优先考虑 llama.cpp/libmtmd issue。普通识图或 OCR 错误首先视为模型质量结果，不能直接归因于上游代码。

## 提示词鲁棒性测试

固定图片和 JSON Schema，分别使用简短中文、带定义中文、英文和证据优先中文；正序运行两次、倒序运行一次。

| 任务 | 提示变体通过 | 唯一答案数 | 结论 |
| --- | ---: | ---: | --- |
| 柱状图趋势 | 4/4 | 1 | 本轮四种问法一致正确，但与 Phase 11 结果存在跨阶段漂移 |
| 人物动作 | 3/4 | 2 | 证据优先措辞稳定返回 clapping，其余三种返回 pointing |

实际结果记录于 `results/phase-13-prompt-robustness.md`。三轮共 24 次请求结果模式一致，已排除普通随机波动、请求顺序和图片缓存污染。

## 并发与资源测试

同一 Dashboard 图片使用唯一 request ID，同时发送 1、2、4 个请求；每一级使用全新服务器，检查正确性、串线、延迟、吞吐、RSS 和 swap。

| 并发 | 正确请求 | 批次耗时 | 吞吐量 | 峰值 RSS |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 1/1 | 4.549 s | 0.220 req/s | 8369.75 MiB |
| 2 | 2/2 | 8.733 s | 0.229 req/s | 8551.41 MiB |
| 4 | 4/4 | 16.820 s | 0.238 req/s | 8605.72 MiB |

实际结果记录于 `results/phase-14-concurrency-scaling.md`。所有响应正确且 swap 未增加；并发扩展稳定，但吞吐提升有限、单请求等待接近线性增加。

## 多图排列

`MULTI-001` 至少运行以下顺序：

- A → B → C
- C → A → B
- A → A → C

这样可以区分“只读取第一张”“忽略重复图片”“答案按固定顺序而非输入顺序”等问题。

## 视频测试

已通过 llama.cpp 原生 `--video` 路径完成短 MP4、无音频 MP4、faststart 与尾部 `moov`、可变时间戳、极短视频、Unicode 文件名以及损坏容器超时保护。

结果记录于 `results/phase-5-video-baseline.md` 和 `results/phase-6-video-boundaries.md`。测试仍分开评估容器、解码、抽帧、时间戳和模型回答，避免把视频 OCR 或时长比较错误误判为 libmtmd 问题。

## 复现资产

运行：

```bash
scripts/generate_boundary_images.sh
```

生成内容位于 `tests/fixtures/`：

- `manifest.json`：用例、问题、判定条件、尺寸、格式、SHA-256。
- `contact-sheet.png`：有效图片的视觉总览。
- `images/`：单图、OCR 与格式边界。
- `multi/`：多图顺序测试。
- `invalid/`：故意损坏或无效的输入。
