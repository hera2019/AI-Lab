# Phase 1 · iPhone 同文对照的三重核验与跳句定位

本文件是 [`phase-1-iphone-repeat.md`](phase-1-iphone-repeat.md) 的后续核验记录。原记录留下的未决问题是「是否有漏读或改词需要通过试听确认」；本次已确认，并定位到具体位置与成因。

---

## 1. 核验方式：三重独立确认

| # | 来源 | 性质 |
|---|---|---|
| 1 | 本人直接试听 | 人耳判断 |
| 2 | macOS「语音备忘录」转写 | 系统内建 ASR |
| 3 | whisper.cpp 本地转写（本 Lab 的 Whisper 项目） | 独立离线 ASR |

三者指向同一处，因此可以排除两种替代解释：

- **不是 ASR 识别错误** —— 两套彼此独立的识别系统结论一致，且与人耳一致。
- **不是文件被裁剪** —— 漏掉的是**中间连续的一段**，其后的内容完整读到结尾。若是裁剪，结尾会缺失。

**结论：这是长文本一次性生成时发生的跳句（skip），不是识别问题，也不是文件问题。**

---

## 2. 跳句的确切位置

模型正常读到：

> 我重新录一个吧，刚才的语音不太好。我们现在呢，可以重新**按照**

然后跳过了以下 **40 个字符（36 个汉字）**：

> ~~我现在说的话，再重新克隆一下我的语音。我现在说话呢，就像平时说话一样。你要是觉得~~

直接续到：

> **我现在说话的声音**有什么听不清楚的，可以问我。如果没有问题，那……

其后完整读至结尾。

### 成因分析

目标文本中「我现在说……」这个片段**出现了三次**：

| 出现 | 上下文 |
|---|---|
| ① | 可以重新按照**我现在说的话**，再重新克隆…… |
| ② | **我现在说话呢**，就像平时说话一样。 |
| ③ | 你要是觉得**我现在说话的声音**有什么听不清楚的…… |

模型读完「按照」之后，本应对齐到 ①，却对齐到了 ③，中间的 ①②整段被跳过。

这是自回归 TTS 在**重复 n-gram** 上的文本—语音对齐串行，机制类似人朗读时眼睛从一行跳到下面相似的一行。

### 一个被推翻的猜测

这同时排除了「模型只能生成约 35 秒」的假设。模型并没有在 35 秒处被截断——它读完了全文的结尾，只是中途少读了一段。**生成长度不是硬上限，对齐稳定性才是问题。**

## 3. 语速数据的修正

原记录中「克隆时长只有原声 59.26%，相当于约 1.69 倍语速」的推断，**建立在文本被完整读出的前提上**。该前提现已被推翻，必须重算。

| 项目 | 数值 |
|---|---:|
| 目标文本汉字数 | 214 |
| 漏读汉字数 | 36（16.8%） |
| 克隆实际读出 | 178 字 |
| 原声速率 | 214 ÷ 60.160 = **3.557 字/秒** |
| 克隆速率 | 178 ÷ 35.650 = **4.993 字/秒** |
| **修正后语速比** | **1.404×** |
| ~~未校正的错误值~~ | ~~1.688×~~ |

### 这个修正改变了结论的性质

原判断是「克隆语速失控，漂移接近 70%」。修正后是 **1.40×**，而且需要注意参照物本身的性质：

- 原声 3.557 字/秒 是**自然对话语速** —— 含「嗯」、思考停顿、口语重复。
- 克隆 4.993 字/秒 是**朗读语速** —— 接近中文有声书的常见区间（约 4–5 字/秒）。

也就是说：**模型并非「读得太快」，而是把一段对话录音当作朗读稿来读。**参照物是对话，产出是朗读，两者语速本来就不同。

对于「用对话录音克隆音色、再朗读其他文本」这个用途，4.99 字/秒是**正常且合适**的。真正的语速失控证据需要用**朗读体参考音频**重测才能确认。

> 待补测项：用一段朗读体参考音（而非对话录音）重跑同文对照，量出朗读—朗读条件下的真实语速比。

## 4. 声音相似度（补记本人与家人的评价）

原记录的主观检查清单当时未填写，`README.md` 因此写为「相似度尚未通过」。该结论**并非评价结果，而是评价缺失**——本人当时未回填。现补记：

### 本人评价

- 听起来**很像**。
- 克隆语速偏快，与原声有差距，但**问题不大**。

### 家人评价（原声与克隆声对照试听）

- 克隆声听起来**更年轻一些**。
- **部分尾音**与本人略有不同。
- **整体相似度较高。**

### 修正后的相似度结论

> **相似度较高。**熟悉本人声音的家人在 A/B 对照下能认出是同一人，主要差异集中在**感知年龄**（偏年轻）与**尾音处理**；本人认为差异主要来自语速。
>
> 这与 Phase 1 早期「旧录音基线」的结果不同：那一次家人认为「语气、语速、发音位置和音色均不像」。差异来源是**参考音频质量**——旧基线用的是条件较差的旧录音，本次用的是 60 秒 iPhone 自然说话录音。
>
> **推论：参考音频的质量与自然度，对克隆相似度的影响大于其他单一因素。**

### 主观检查清单（回填）

- [x] 是否完整读出相同文字 —— **否**，中间跳过 40 字符（见第 2 节）
- [x] 音色是否像 —— 像；家人认为略偏年轻
- [x] 发音位置与咬字是否像 —— 基本像；部分尾音有差异
- [x] 语速是否像 —— 偏快（1.40×），但属朗读语速与对话语速之差
- [ ] 句内停顿是否像 —— 未单独评价

## 5. 本次最重要的结论

> **声音听起来像，不代表内容完整。**

这是一个只有做了回读核验才会发现的问题：音色、韵律、自然度全部正常，人耳听不出任何异常——因为跳过的部分**在听感上是连贯的**，它读出来是一句通顺的话，只是不是原文那句话。

对于真正用于视频配音、播客或有声读物的场景，**生成之后必须做一次 ASR 回读校验**，把生成音频转写回文字，与目标文本比对。这不是可选的质量加分项，而是必需的正确性检查。

本 Lab 恰好已经具备这个能力（`whisper-large-v3-turbo-whispercpp`）。TTS 项目的测试计划中原本就写了「以后可以组合成转录、翻译、配音和字幕流水线」——本次事件说明，这个组合不只是功能扩展，而是**质量保障的必要环节**。

## 6. 下一步

### 6.1 分句生成（Phase 2 前置）

把目标文本按句切分，逐句独立生成，再按顺序合并成一个 WAV。

理由：跳句发生在**长文本一次性生成**中；单句文本长度短、重复 n-gram 少，对齐串行的概率大幅下降。

每段结果应记录：

```
第 N 段：目标文字 / 生成时长 / 回读文本 / 相似度 / 是否完整
```

### 6.2 回读校验流程

```
逐句生成 → whisper.cpp 回读（开启 VAD）→ 与该句目标文本比对相似度
        → 低于阈值 → 标记「需人工确认」并可重新生成该句
```

⚠️ 边界（来自本 Lab Phase 3 实测）：纯静音会使 Whisper 生成 `Thank you.` 幻觉，VAD 可消除。回读结果是**另一个有噪声的观测**，不是真值，只用于标记，不用于自动改写文本。
