## 0. 前提确认

审计开始时，七个项目**均不是 git 仓库**。

这一条改变了审计的性质：

- **没有 git 历史需要清理。**不存在「文件当前被 ignore、但曾经被提交过」的风险——这通常是这类审计里最麻烦的一项。
- 但也意味着**不存在可作为证据的既有提交历史**。首次提交是一次全新导入，时间证据从公开之日起算。

## 2. 关于声音资料的原则

本仓库同时包含语音识别与声音克隆研究。发布任何真人录音，等于**同时提供声纹样本与克隆方法**。

因此采用的规则不是「排除敏感内容的录音」，而是：

> **整类排除，不区分内容是否敏感，包括作者本人的录音。**

这条规则写进了仓库根 `.gitignore`，并在两份 README 的「伦理与隐私」一节公开说明。

## 3. 脱敏工具

绝对路径与逐字稿的处理由 [`tools/redact_for_publication.py`](../tools/redact_for_publication.py) 完成，而非手工编辑。理由：464 处手改必然出错，且不可复现、不可复核。

工具的四条设计约束：

1. **只做机械替换**，判断留在本报告里。
2. **不破坏可运行性**——脚本中的路径替换为等价表达式，不是占位符：

   | 文件类型 | 替换 |
   |---|---|
   | `.py` | `"/Users/X/REST"` → `str(Path.home() / "REST")` |
   | `.sh` | `/Users/X/` → `$HOME/` |
   | `.md` `.json` `.log` `.txt` `.csv` | `/Users/X` → `~` |

3. **不破坏可验证性**——时长、采样率、RTF、内存、seed、SHA-256 一律不动。
4. **幂等**，且**遵守 `.gitignore`**——只处理会被发布的文件，不改动本地记录。

### 工具本身暴露的两个缺陷（已修）

**其一：打断了隐式字符串拼接。**Python 允许 `"a" "b"` 自动拼接，但 `str(...) "b"` 是语法错误。原文中有这样的写法：

```python
DEFAULT_LLAMA_SERVER = Path(
    "/Users/X/Documents/AI-Lab/qwen3-14b-llamacpp/"
    "worktrees/llama.cpp/build-release-metal/bin/llama-server"
)
```

替换后前一段成了表达式，拼接断裂，3 个文件无法编译。工具已加入 `repair_implicit_concat()` 补回显式 `+`。

**其二：目录跳过规则过宽。**`SKIP_DIRS` 中的 `tools` 本意是跳过脱敏工具自身，却连带跳过了 whisper 项目自己的 `tools/`，漏掉了 A6。已改为按文件路径精确跳过工具自身。

> 这两个缺陷都是被**验证步骤**抓出来的，不是被审查代码抓出来的——见下一节。

## 4. 验证

### 4.1 一次差点漏掉的假通过

第一轮验证在 `git add` **之前**执行，用的是 `git ls-files`——在空索引上它返回空列表。于是「Python 全部编译通过」和「零用户名残留」两项都是**在零个文件上通过的**。

重做验证（先 `git add -A`，再在真实索引上检查）立刻暴露了 3 个编译失败与 1 处用户名残留，即上一节的两个缺陷。

> 记下来是因为它和本仓库反复出现的主题是同一件事：
> **一个「通过」的结果，先要问它检查了什么。**
> 一次在空集合上执行的检查，永远通过。

## 5. 仓库结构决定：单仓库

七个项目合为一个仓库 `ai-lab`，而不是七个独立仓库。

**理由**：这批工作的价值主张是「**在固定硬件预算下横向验证七类模型**」——这个论点只有在它们放在一起时才成立。跨项目的结论（语音识别 + 语音合成 = 回读校验）分开就看不见了。而且顶层 README 是招聘方唯一会读的入口，只能有一个。

体积 24.9 MB，对单仓库完全没有压力。

**可逆**：将来若某个项目需要独立发布，`git subtree split` 可以拆出去并保留该子树历史。
