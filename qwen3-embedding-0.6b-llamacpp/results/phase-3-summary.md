# Phase 3：完全本地 RAG 总结

日期：2026-09-06（Asia/Tokyo）

## 实际意义

Phase 2 只能找出相关资料，Phase 3 在检索结果之上增加了本地问答模型。现在可以直接用自然语言询问 AI-Lab 的实验记录，系统会先寻找相关段落，再依据这些段落回答并标注来源。检索与回答都在本机执行，不依赖网络 API。

## 最终结构

1. `Qwen3-Embedding-0.6B Q8_0` 把问题变成 1024 维语义向量。
2. 在 70 个 Markdown 文件、497 个段落的持久化索引中检索候选内容。
3. 最多选择 5 个来源，同一文件最多 2 个段落，总资料不超过 7000 字符。
4. 向量进程退出后，再启动 `Qwen3-4B-Instruct-2507 Q8_0` 生成答案，因此两个模型不会同时常驻内存。
5. 问答模型只能使用本轮来源；资料中的提示或命令被视为不可信文本。
6. 有依据的结论必须使用 `[S1]` 形式引用；资料不足时必须输出固定拒答句。

问答模型固定使用 Metal、8192 上下文、最多生成 600 tokens、关闭 reasoning，并设置固定 seed。中、日、英问题分别附加明确的目标语言指令。

## 最终评测

- 结果：4/4 通过。
- 四题总墙钟时间：25.653 秒。
- 平均每题：检索 0.880 秒，问答模型 5.515 秒，合计 6.413 秒。
- 峰值常驻内存：5,599,461,376 bytes，约 5.22 GiB。
- swap：0。

| 案例 | 目的 | 结果 | 合计时间 |
| --- | --- | ---: | ---: |
| RAG-Q01（中文） | 从视频实验中解释猫眨眼为何只算部分成功 | PASS | 7.258 秒 |
| RAG-Q02（日文） | 判断票据中的 TP 是商品名还是独立列 | PASS | 7.343 秒 |
| RAG-Q03（英文） | 回答四并发的吞吐量与延迟变化 | PASS | 6.910 秒 |
| RAG-Q04（中文） | 对资料中没有的购买地点和价格拒答 | PASS | 4.139 秒 |

人工复核结论：四个最终答案的核心结论均受所引资料支持；英文数字为吞吐量提升 8.2%，平均延迟由 4.55 秒升到 16.79 秒；未知购买信息按要求拒答。日文答案正确判断 TP 为独立列，不过措辞仍略显啰嗦，并在正文中重复提到来源编号，属于风格问题而非事实错误。

## 修正过程

失败没有被覆盖，保留了三份中间报告：

- `results/phase-3-rag-evaluation-initial.md`：3/4；日文问题的事实正确，但回答混入中文且引用格式不稳定。
- `results/phase-3-rag-evaluation-after-format.md`：2/4；日文改善，但英文偶尔改用中文；中文同义表述被评测器误判。
- `results/phase-3-rag-evaluation-before-citation-normalization.md`：3/4；三种语言均正确，中文答案仅因模型输出 `[ S1 ]` 而不是 `[S1]` 被判失败。

最终改进包括：按问题语言动态追加明确指令；让自动评测接受真实同义表述；仅规范化引用括号内的无意义空格；为这些行为增加单元测试。最终 8 项单元测试通过。

## 使用方法

单次提问：

```bash
scripts/ask_ai_lab.sh "为什么猫眨眼的测试只算部分成功？"
```

连续提问：

```bash
scripts/ask_ai_lab.sh
```

重新运行四案例评测：

```bash
scripts/run_phase_3.sh
```

每次答案及完整来源会写入 `results/rag-last-answer.md` 和 `results/rag-last-answer.json`。最终评测在 `results/phase-3-rag-evaluation.md` 和对应 JSON 中。

## 边界与结论

- 引用检查能确认编号存在、事实段落带引用，却不能自动证明每个句子真的被来源蕴含；仍需抽样人工复核。
- 4B 模型偶尔会切换语言、变得啰嗦或产生引用空格，说明生产系统需要明确语言控制与轻量格式校正。
- 每次问题都重新加载两个模型，适合实验和偶尔查询；若追求连续低延迟，应让服务进程常驻。
- 检索命中不等于问题可回答。固定拒答测试证明系统已经具备基础的“没有资料就不猜”能力，但不能据此断言所有未知问题都能稳定拒答。
- 这套 RAG 没有训练模型，也没有联网。它只是把已有实验资料检索出来，交给本地模型做受约束的整理与回答。

结论：Phase 3 已把 AI-Lab 的语义索引升级为可实际使用的完全本地问答系统。就当前 70 个文件的规模而言，准确性、速度和内存占用均达到本阶段目标。
