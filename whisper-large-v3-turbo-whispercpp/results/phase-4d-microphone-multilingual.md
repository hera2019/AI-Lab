# Phase 4D：中日英逐句自动识别与互译

测试日期：2026-09-03

## 实际应用意义

固定中文输入要求用户先选择语言，不适合跨语言对话。本阶段让每个 Silero 语音段由 Whisper 自动判断中文、日文或英文，保存声学置信度和原始转写，再由本地 Qwen3-4B 补齐另外两种字幕。

源语言文字不会交给翻译模型改写。这样可以明确区分“Whisper 听错”和“Qwen 翻错”，也避免流畅译文掩盖原始识别错误。

## 实现

新入口：

```bash
scripts/run_microphone_multilingual.sh
```

它复用 Phase 4C 已验证的麦克风、Silero 流式 VAD、Whisper 和 Qwen 服务，但把 Whisper 请求改为 `language=auto` 和 `response_format=verbose_json`。详细响应提供检测语言、检测置信度以及各语言概率。

每句日志保存：

- Whisper 原始文字和自动检测语言
- 检测语言置信度
- 中文、日文和英文字幕
- 最近两句只读上下文
- Whisper、Qwen 和合计处理时间
- 对应 WAV、时长和 Silero 峰值概率

置信度低于 0.50 时，终端会显示核对提醒。每个语音段只假设一种主要语言；一句内部频繁混用多种语言仍是已知边界。

## 真人麦克风验证

固定朗读稿位于：

```text
tests/microphone-multilingual-script.md
```

真人使用 `OpenFit by Shokz` 依照固定稿连续切换中文、日文和英文。原始数据：

```text
results/microphone-multilingual/runs/20260903-140429-92832/summary.json
```

朗读中的句内停顿多次超过约 0.83 秒，因此九行固定稿实际形成了 19 个语音片段，另有一个 0.576 秒的开场可疑片段。这反映了实时逐句系统的真实边界：停顿决定分句，不一定与书面句号一致。

### 识别结果

- 中文片段均正确判断为中文，置信度为 0.9909–0.9978；日期、下午 3:15 和 A731 被正确识别。
- 英文片段均正确判断为英文，置信度为 0.9473–0.9997；日期和时间正确，但口述 `A seven three one` 有一次被识别为 `8731`。
- 短日语 `はい、よくわかります` 和 `わかりました。ありがとうございます` 均完整识别，语言置信度约 0.995。
- 较长的日语日期/会议句因发音和多次停顿切成六段，其中四段判断为日语，一段误判为中文，一段以 0.3993 的低置信度误判为越南语；文字也有明显错误。标准日语音频表现良好，因此本次差异主要与真人发音、停顿和短片段有关，不能解释为日语路径完全失效。

17 个成功处理片段的 Whisper 平均耗时为 1.299 秒，双语翻译平均 0.618 秒，定稿后计算平均 1.917 秒。加上约 0.83 秒句末静音确认，平均完整字幕延迟估算约 2.75 秒，范围约 2.50–3.13 秒。

### 实测发现并修复的程序问题

首次实测暴露了三个应用层问题：

1. Qwen 偶尔把英文或日文原文复制进中文字幕。
2. `好，我知道了` 一度被翻成否定的 `No / いいえ`，英语 `I/you` 的日语主客体也曾颠倒。
3. 真实说出的 `Thank you.` 被静音幻觉固定词表误删。

翻译接口现只要求 Qwen 生成另外两种目标语言；源语言由程序直接保留。提示也明确约束肯定/否定和说话视角。固定词过滤现只自动删除短于 0.75 秒的候选；较长的同名短语会保留并显示核对提醒。

使用真人原声片段回归后：

```text
→ 是的，我清楚地理解你。
→ はい、あなたの言っていることがよくわかります。

わかりました。ありがとうございます。
→ 好的。谢谢。
→ Okay. Thank you.

Thank you.
→ 谢谢。
→ ありがとう。
```

四段均保留正确源文、正确检测语言且无处理错误。回归数据：

```text

```

## 结论

Phase 4D 已完成。中、日、英逐句自动语言判断、本地转写、双向互译、上下文、真实麦克风、置信度和延迟都已验证；测试中发现的确定性应用问题也已修复并用原声回归。

本项目不声称识别率达到 100%。真人日语发音、句内长停顿、字母与数字（如 A731）以及极短词仍需人工核对。这些是本轮诚实保留的模型和输入边界，不阻止研究阶段收尾。

长时间会议、多人说话轮次和说话人身份不是本轮收尾条件；它们属于未来产品化时的独立专项。
