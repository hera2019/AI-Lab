# Phase 4C：中文麦克风与中日英字幕

测试日期：2026-09-03

## 实际应用意义

目标场景是用户说中文，界面保留可核对的中文字幕，同时提供日文和英文翻译。中文原文必须优先显示，因为翻译模型可能误解分词；日期、时间和编号必须在三种语言中保持一致。

## 最终链路

```text
OpenFit by Shokz 麦克风
  → 16 kHz 单声道 PCM
  → Silero VAD 连续人声检测
  → 停顿约 0.83 秒后形成一句 WAV
  → whisper.cpp large-v3-turbo-q5_0 中文识别
  → 时间格式消歧
  → Qwen3-4B Q4_K_M 同时翻译日文和英文
```

采音器每 64 ms 处理一帧。默认要求连续两帧人声概率达到 0.20 才开始记录，并在连续约 0.83 秒低于阈值后定稿。它使用 `whisper_vad_detect_speech_no_reset()` 保留 Silero 的流式状态，不修改 whisper.cpp 源码。

## 为什么没有继续使用 whisper-stream 的简易 VAD

第一轮滚动识别能够听到中文，但静音时反复产生 `谢谢观看`，并生成过一条“点赞订阅……”类幻觉。6 秒窗口还重复输出旧文字。

第二轮将 `whisper-stream` 切换到内置简易 VAD 后，仍有三个问题：

- 同一句被重叠窗口反复识别。
- `明天下午3:15分开会` 被 4B 翻译模型错误切成“分开”，日文成为 `別れます`，英文成为 `separate`。
- 静音幻觉不只一种，维护禁止词列表不能解决根因。

因此最终方案改为独立的 Silero 流式门控，并在翻译前把 `3:15分` 这类形式规范为无歧义的 `3点15分`。失败数据保存在 `results/microphone-trilingual/live-001` 和 `results/microphone-trilingual/live-002`。

## 夜间小声校准

Silero 阈值 0.50 时，安静背景概率通常为 0.00–0.04，小声输入一度只达到 0.46，因此没有形成稳定语句。默认阈值随后调整为 0.20，并将启动条件从连续三帧缩短为连续两帧。该阈值针对本次耳机麦克风和安静房间，不应视为所有设备的通用最佳值。

## 最终真实麦克风结果

输入设备：`OpenFit by Shokz`，16 kHz、单声道、float PCM。

实际语音期间 Silero 概率达到 0.97–1.00。最终字幕为：

```text
中文字幕：明天下午3:15开会订单号是A731
日本語字幕：明日午後3時15分に会議を開きます。注文番号はA731です。
English: A meeting will be held at 3:15 PM tomorrow. The order number is A731.
```

| 指标 | 结果 |
| --- | ---: |
| 保存的语音段长度 | 5.504 秒 |
| Silero 峰值人声概率 | 1.000 |
| Whisper 中文识别 | 0.642 秒 |
| Qwen 日英双语翻译 | 1.166 秒 |
| 定稿后的计算时间 | 1.808 秒 |
| 估算说完到三语全部显示 | 约 2.64 秒 |
| 日期/时间/编号 | 时间和 A731 均正确 |
| 重复字幕块 | 0 |

约 2.64 秒由约 0.83 秒停顿确认和 1.81 秒识别/翻译组成。当前程序没有保存最后一个发声帧的绝对时间，因此这是依据固定静音门限计算的估计值，不是假装成更精确的实测数字。

低阈值曾让一个很短的候选通过 Silero，Whisper 将其识别为 `谢谢观看`；应用层识别为常见静音套话并忽略。之后长时间静音没有显示正式字幕。这说明 Silero 显著改善问题，但在极低阈值下仍不是绝对保证，未来应增加最短有效语音、信噪比和多环境测试。

完整结果保存在 `results/microphone-trilingual/live-004-silero-quiet/summary.json`，触发的语音段也保存在同目录的 `segments/`，便于复核。

## 使用方式

```bash
scripts/run_microphone_trilingual.sh
```

说中文，句末安静约一秒；按 `Ctrl-C` 正常停止。程序会自己启动和关闭本地 Whisper、Qwen 服务。

默认结果保存在独立运行目录：

```text
results/microphone-trilingual/runs/YYYYMMDD-HHMMSS-PID/
```

因此连续运行不会再覆盖此前的 `summary.json`、服务日志和语音片段。只有显式指定同一个 `--output-dir` 时，才会复用指定目录。

翻译会携带最近两句已确认的中文字幕作为语境，但提示明确要求只翻译当前句，不得重复前文，也不得修改中文听写。实际传入的两句上下文会记录在每个事件的 `translation_context` 字段中，便于审计。

在固定复测中：

```text
前文：这个软件什么都能听得懂啊
前文：你能听懂吗
当前：好
```

原先错误的 `こんにちは / Hello` 已变为符合对话的 `いいですね / Good`，翻译耗时 0.591 秒。复测保存在 `results/microphone-trilingual/runs/20260903-011648-54591/summary.json`。

如需重新构建采音器：

```bash
scripts/build_mic_silero_capture.sh
```

## 结论与边界

中文麦克风到中、日、英稳定字幕已经在真实设备上跑通，时间和订单号保持正确。当前约 2.6 秒更接近“逐句字幕”而非电视式逐字字幕。它只验证了一句话和一个安静环境；噪声、多人、连续长句、不同麦克风及数字准确率仍需扩展样本，翻译结果也不能用于无需人工复核的高风险业务。
