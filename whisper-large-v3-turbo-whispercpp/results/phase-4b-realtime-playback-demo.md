# Phase 4B：实时字幕播放模拟

测试日期：2026-09-03

## 实际应用意义

批处理速度快于音频时长，只能证明模型最终能追上录音，不能说明字幕会在什么时候出现。本测试按正常时间轴逐步送入音频，观察临时日文、稳定日文和中文翻译的实际等待时间，为会议字幕、视频直播字幕和明天的真实麦克风测试建立基线。

## 测试方式与边界

- 音频：`tests/fixtures/audio/asr-ja-001.wav`，10.153 秒。
- 内容：今天是 2026 年 9 月 2 日；会议下午 3:15 开始；订单号 A731。
- 音频通过耳机以 1.0 倍速播放，同时程序按播放时间切取已经“到达”的 PCM 音频。
- Silero VAD 预先得到三段语音：0.10–3.29、3.52–6.65、6.88–10.153 秒。
- 每段讲话期间约每 1.35 秒生成一次临时日文；停顿后 0.25 秒提交定稿识别，再交给本地 Qwen3-4B 翻译。
- Whisper 和 Qwen 均由持久本地服务加载，避免把模型启动时间误算成每句字幕延时。
- 这不是系统回环录音，也没有使用麦克风；VAD 边界已预先计算。因此它验证了字幕处理链路和近实时计算能力，但不能代替真实采音、实时 VAD 与环境噪声测试。

## 结果

| 指标 | 实测 |
| --- | ---: |
| 临时日文首次出现（相对该句开始） | 约 1.84–1.87 秒，平均约 1.86 秒 |
| 临时识别完成（相对当前音频切点） | 约 0.49–0.54 秒 |
| 稳定日文（相对该句语音结束） | 平均 0.753 秒 |
| 中文字幕（相对该句语音结束） | 平均 0.953 秒 |
| 翻译比稳定日文增加的等待 | 平均约 0.200 秒 |
| 处理错误 | 0 |

正常速度下没有形成处理积压。三句定稿结果为：

```text
今日は2026年9月2日です。
会議は午後3時15分に始まります。
注文番号はA731です。
```

```text
今天是2026年9月2日。
会议于下午3点15分开始。
订单号是A731。
```

临时字幕体现了流式识别的正常修订过程：`今日は2022` 后来纠正为 `今日は、2026年9月2日。`，`注文番号はA734` 在句末纠正为 `注文番号はA731です。`。因此界面必须明确区分“可能变化的临时字幕”和“可保存的稳定字幕”，不能把临时数字直接记入业务数据。

完整逐事件计时保存在 `results/realtime-playback-demo/live/summary.json`。

## 英文临时字幕是否天然更快、更准确

不一定更快。本演示的刷新速度主要由音频分块间隔和推理耗时决定，换成英文不会自动缩短 1.35 秒的分块时间。英文有单词空格，用户更容易看懂逐词增长；日文没有天然空格，汉字选择和句末语法又常依赖后文，所以日文临时片段在视觉上通常更容易发生修订。

准确率也不能简单归因于“英文同音词少”。英文同样有很多同音词；Whisper 会同时利用声音和上下文判断。语言、口音、领域词汇、录音质量和训练数据覆盖度往往比同音词数量更重要，需要用同样难度的英文与日文录音实测。

## 明天的麦克风测试

已经额外编译带 SDL2 和 Metal 的 `whisper-stream`，没有修改 whisper.cpp 源码。日文麦克风入口为：

```bash
scripts/run_microphone_japanese.sh
```

首次运行时 macOS 可能请求麦克风权限；说日语，按 `Ctrl-C` 停止。先确认实时日文、输入设备、噪声和响应速度，再把稳定日文接入已经验证的 Qwen3-4B 中文翻译。真实麦克风预计还会增加采音缓冲和实时停顿判断时间，最终数字必须以明天实测为准。

## 结论

M2 Max 能在正常语速下完成本地日语临时字幕，并在一句话结束后平均约 0.75 秒给出稳定日文、约 0.95 秒给出中文。计算性能足够进入真实麦克风测试；当前结果不能声称已经验证真实直播环境。
